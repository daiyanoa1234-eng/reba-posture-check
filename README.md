# REBA 姿勢評価（端末内解析 PWA）

建設現場でスマホから使う、REBA（Rapid Entire Body Assessment）の姿勢評価 Web アプリです。
最大20秒の作業動画から骨格（関節点）を推定し、推定角度・3D骨格・REBA の仮評価を表示します。最後に評価者が手動項目と姿勢を確認して評価を確定・保存します。

- 公開版: https://daiyanoa1234-eng.github.io/reba-posture-check/
- 動画と解析結果は **端末内のブラウザで処理し、外部に送信しません**。動画は保存しません。
- ログイン・有料 API・クラウド保存は使いません。

> **注意**: 角度・スコアは画像からの推定に基づく参考値です。本アプリの臨床的・研究的な妥当性は検証されていません。撮影区間の1場面の評価であり、作業全体の評価ではありません。最終判断は評価者が行ってください。

## できること

| 段階 | 機能 |
|---|---|
| 1. 動画 | アプリ内撮影（背面カメラ、**20秒で自動停止**）／保存済み動画の選択／20秒超の動画は解析区間（開始位置・長さ）を選択／非対応形式の案内 |
| 2. 解析 | MediaPipe Pose Landmarker（軽量モデル初期値）で毎秒5フレーム（2/5/10/15 に変更可）を端末内で推定。進捗・経過時間・キャンセル・モデル読み込み状態を表示。解析時間を計測して結果に表示 |
| 3. 候補 | 姿勢負担が高いと推定される場面を最大3つ提示（一瞬の推定エラーは除外、前後フレームでの持続を確認、複数人・全身外のフレームは除外）。グラフ・スライダーで選び直し可 |
| 4. 確認 | フレーム上に骨格線・関節点・推定角度を表示／部位別の推定角度と REBA 区分の表／3D骨格（推定・回転拡大可・同じ時刻）／評価側（左右）の切替／仮スコア |
| 5. 手動入力 | 1画面・大きなボタンで、重量/力・衝撃・ねじれ/側屈・把持・活動・脚の支持・上腕補正・手首・頸部などを入力。自動推定値の修正も可 |
| 6. 確定・保存 | 確定スコアとリスク区分、部位別点数、手動補正の一覧。評価画像（顔ぼかし初期値ON）・CSV の書き出し、端末内保存（IndexedDB） |
| その他 | PWA（WASM・モデルを同梱してキャッシュし、2回目以降オフライン可）／模擬データで操作を試すモード（画面・保存・書き出しに「模擬データ」と明示） |

## 起動方法（開発者向け）

必要: Node.js 22 以上（20.19 以上でも可）

```bash
npm install
```

```bash
npm run dev
```

- `npm run dev` の前に `scripts/fetch-assets.mjs` が自動で走り、MediaPipe の WASM を `node_modules` から `public/mediapipe/wasm/` へコピーし、同梱モデル（`public/models/`）の SHA-256 を検証します。
- PC のブラウザで http://localhost:5173 を開きます（localhost はカメラ・Service Worker が使える安全なコンテキスト扱い）。

その他のコマンド:

```bash
npm test
```

```bash
npm run build
```

```bash
npm run preview
```

```bash
npm run dev:https
```

`dev:https` は自己署名証明書で LAN 内の HTTPS 配信を行います（スマホから `https://<PCのIP>:5173` で確認する用。証明書の警告が出ます。Service Worker やカメラが動かない場合は公開版で確認してください）。

### GitHub Pages への配信

`main` へ push すると GitHub Actions（`.github/workflows/deploy.yml`）がテスト → ビルド（`BASE_PATH=/reba-posture-check/`）→ GitHub Pages へのデプロイを行います。

## スマホでの使い方

1. スマホのブラウザ（iPhone は Safari、Android は Chrome）で公開版の URL を開く
2. ホームに「オフラインで利用できる状態です」と出るまで待つ（初回のみ約 21MB を取得）
3. ホーム画面に追加（iPhone: 共有 →「ホーム画面に追加」／Android: メニュー →「アプリをインストール」）
4. 「撮影する」または「保存済みの動画を選ぶ」→ 解析 → 場面を選ぶ → 手動項目を入力 → 結果を保存・書き出し

撮影のコツ: 作業者1人の全身（頭から足首）を、できるだけ真横から、スマホを傾けずに縦向きで。

iPhone で撮った動画が Android や一部ブラウザで読めない場合は、iPhone の「設定 > カメラ > フォーマット」を「互換性優先」（H.264）にしてください。

実機での確認手順とチェックリスト: [docs/DEVICE_TEST.md](docs/DEVICE_TEST.md)

## REBA の出典と実装ルール

- 原著: Hignett S, McAtamney L. Rapid Entire Body Assessment (REBA). *Applied Ergonomics* 2000;31(2):201–205.
- Table A・B・C、各補正、リスク区分を独自の簡易計算に置き換えず実装しています。照合した資料（Cornell 大学 A. Hedge 講義資料、Ergonomics Plus ワークシート、INSST NTP 601）と照合結果、資料間の食い違い（Table B の1セル、頸部伸展の表記）、本アプリの取り決め（境界値、直立の許容幅など）は **[docs/REBA_RULES.md](docs/REBA_RULES.md)** に記載しています。
- 原著本文は有料公開のため、開発時に本文での最終確認はできていません。

主な実装ルール:

- 未確認項目は 0点や「なし」とみなさず、取りうる範囲で **仮評価（最小〜最大）** を表示
- 全項目が確認済み かつ 評価者が推定姿勢を確認 → **確定**
- 自動推定値（auto）と手動入力値（manual）を区別して保存し、CSV にも出所を出力
- 部位ごとに別時刻の最大値を集めず、**選んだ1フレームの姿勢だけで採点**
- 左右は作業者本人の左右。上腕・前腕・手首は評価側の値で採点

## 角度の定義

基準姿勢・基準面・符号・計算方法は **[docs/ANGLE_DEFINITIONS.md](docs/ANGLE_DEFINITIONS.md)** にまとめています。要点:

- MediaPipe の推定3次元座標（world landmarks）から計算。画像の上方向を鉛直上方向とみなす（撮影時にスマホを傾けない前提）
- 体幹は「股関節中点→肩中点の線と鉛直線の角度」、頭頸部は「肩中点→耳の線と体幹線の角度（参考値）」であり、**腰椎・頸椎の角度ではありません**
- 自動で区分を設定するのは 体幹・上腕・前腕（肘）・膝 のみ。頸部・手首・ねじれ・側屈・肩の挙上・支持などは評価者が入力（推定値は参考として提示）
- 足関節角度は追加情報として表示し、REBA の採点には使いません
- 関節点の visibility（検出の目安）は角度の精度の保証として扱いません

## 検証状況

### 自動テスト（`npm test`、67件）

- REBA: Table A/B/C 全セル、単調性、範囲外入力、計算例の再現、全補正、座位の扱い、上腕スコアの下限、未確認項目の範囲、確定条件、自動/手動の区別、リスク区分
- 角度区分の境界値（体幹・頸部・上腕・前腕・手首・膝）
- 角度計算: 合成骨格で既知の角度（体幹の前屈/後屈を4方向から、側屈、頭頸部、上腕の屈曲/伸展/外転、肘、膝、手首、足関節）を再現、見えない部位は角度を出さない
- 候補抽出: 持続した高負担姿勢の抽出、一瞬の急変の除外、孤立フレームの除外、複数人・未検出の除外、候補の時間間隔、左右別の指標、一部の関節が見えないフレームの扱い
- CSV（エスケープ・BOM・仮評価・出所）、評価画像の文字折り返し

### PC での動作確認（2026-11-20、macOS・Claude アプリ内の Chromium 系ブラウザ、スマホ幅 375×812 表示）

実データ（屋外の掘削作業の動画、作業者1人＋背景に別の作業員、18秒・720p）で確認:

- 動画の読み込み → 解析（90フレーム）→ 候補3件の提示 → 骨格・角度ラベルの重ね描き → 角度表 → 3D骨格 → 手動入力 → 確定（手計算と一致する REBA 9）→ 結果画像（顔モザイク）→ 端末内保存 → CSV 内容の確認
- 解析時間（**参考値。ブラウザ画面が非表示の状態での計測で、スマホの性能とは異なります**）: 軽量モデル 16.1秒／90フレーム（1フレームあたり 推定 約38ms・動画の読込 約140ms）、標準モデルの推定 約42ms/フレーム
- 45秒の動画で区間選択（12〜32秒）、解析途中のキャンセル、人物が映っていない動画、壊れた動画ファイル、モデル読み込み失敗（通信遮断を模擬）で、案内を表示して画面が止まらないこと
- 本番ビルドで Service Worker が WASM・軽量モデルを含めてキャッシュし、配信サーバー停止後も起動・モデル読み込み・模擬データでの操作ができること
- 模擬データモードで、推定エラーを模したフレームが候補から除外されること

### 未検証（実機で確認が必要）

- **iPhone Safari・Android Chrome での動作はすべて未検証**（アプリ内撮影、MediaRecorder の形式、動画のシーク精度、解析速度、メモリ、共有シートでの書き出し、ホーム画面追加、オフライン起動、屋外での視認性）
- 推定角度の精度（実測との誤差）、軽量モデルと標準モデルのどちらが現場動画に適するか
- 候補抽出が評価者の選ぶ場面と一致するか

## 制約・既知の課題

- 単眼カメラの推定のため、正面/背面からの撮影、遮蔽（工具・資材・保護具）、逆光・暗所、遠距離では角度が不安定になります
- カメラの傾き補正はしていません（スマホを傾けずに撮影）
- 対象は作業者1人。複数人が映るフレームは候補から除外し、確認を促します
- 顔ぼかしは、評価対象者と「検出できた」他の人物の頭部にモザイクをかけます。検出できなかった人物、看板、車両番号などには適用されないため、共有前に画像を確認してください
- 解析中は動画をメモリ上に保持します。長時間・高解像度の動画では端末によってメモリ不足になる可能性があります（フレーム画像は長辺 960px に縮小）
- 保存データはブラウザ内（IndexedDB）にあり、ブラウザのデータ消去等で消えます。必要に応じて CSV・画像で書き出してください
- 初回は約 21MB（WASM 約14.7MB、軽量モデル約5.8MB ほか）の取得が必要です。標準モデル（約9.4MB）は選択時または詳細設定から取得します

## 技術構成

- Vite 8 + TypeScript + Preact
- 姿勢推定: `@mediapipe/tasks-vision`（Pose Landmarker、IMAGE モード、CPU 初期値／GPU 選択可）。WASM とモデルを同梱し、実行時に CDN を使いません
- 3D: Three.js（必要時に動的読み込み）
- PWA: `vite-plugin-pwa`（Workbox。WASM と軽量モデルをプリキャッシュ）
- 保存: IndexedDB／書き出し: JPEG・CSV（UTF-8 BOM）
- フレーム画像の JPEG 化は Web Worker（OffscreenCanvas）で解析と並行実行

```
src/
  app.tsx               画面遷移と状態
  screens/              ホーム・撮影・準備・解析中・場面選択・手動入力・結果・履歴・設定・使い方
  components/           フレーム表示・タイムライン・角度表・点数表・3D・共通UI
  lib/pose/             MediaPipe の読み込み・推論、関節番号
  lib/video/            動画読み込み・シーク・JPEG 化
  lib/analysis/         解析ループ・検出状態の判定
  lib/angles/           角度計算
  lib/reba/             採点表・区分・採点・自動提案
  lib/selection/        評価候補の抽出
  lib/storage/          IndexedDB 保存
  lib/export/           骨格描画・顔モザイク・評価画像・CSV
  lib/demo/             模擬データ（テスト・デモ専用）
docs/                   REBA 実装ルール・角度定義・実機確認手順
public/models/          姿勢推定モデル（Apache-2.0）
```
